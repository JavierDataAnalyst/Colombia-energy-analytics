What drives Colombia's electricity price?

How it is built

Four layers, each one only reading from the one before. Every figure on this page comes from layer 3.

  1. Layer 1 · Sources

    Raw, untouched, never overwritten

    Python calls the XM public API month by month. Each response is stored as received with its load timestamp. A month with a missing day or hour is rejected whole, and every load is logged in a control manifest.

    etl/ingest.py
  2. Layer 2 · Model

    Star schema in dbt

    Facts by date × hour (system) and date × hour × plant, with date and plant dimensions. Plants missing from XM's list go to an exceptions table instead of being dropped.

    dbt/models/core
  3. Layer 3 · Metrics

    Defined once, documented

    Demand-weighted spot price, inflows vs. historical mean, reservoir level, generation mix and hourly profile, each with a card in the data dictionary.

    dbt/models/metrics
  4. Layer 4 · Product

    This page and the charts

    A script reads only the certified metrics and exports small JSON files. A weekly GitHub Actions job rebuilds everything.

    app/build_report.py

Stack: Python · DuckDB · dbt · GitHub Actions · Chart.js. No paid services.

Data quality: every test can fail

Results of the latest dbt test run.

    The accuracy test reconciles two independent XM publications, plant-level and system-level generation, every day. If they disagree by more than 0.5 %, the build stops before any chart is published.
